# S1 — SURFACE ADAPTATION

*Reader: DM, Jake. Builds on `A1-campaign-brief.md` and `C2-factions-clocks.md`
— read both first; this file does not restate the premise, the pillars, or
the faction/clock entries. Cites `C3-the-salts-as-background.md` for the
Salts loop this file is adapting away from, and `novel/canon.md` §2 (ability
hard limits) and §5 (world, the Salts) throughout. No `campaign/system/`
ruleset exists yet (`DECISIONS.md` Q-1) — every mechanic below is a
structural proposal, tagged `(untested)` per `PLAN.md`'s own instruction for
this file, and every number it would need is marked `(SYS?)`. This file
decides shapes, not numbers; Jake's real ruleset supplies the numbers once
it lands in `campaign/system/`, and nothing here should be read as final
until it does.*

## How to use this file

Jake's Deep Salts ruleset (d20 base, six attributes, limb targeting, status
effects, mutation, Insight, stopwatch parry) was built for the Salts loop:
anchor chalice, hub, bail-out, a Token economy, no fast travel
(`source-bible.md` → Rules, "The Salts loop"). The campaign proper runs on
the surface, in real towns, on a real rail line, across real seasons — a
different shape of play that the loop's own economy and travel rules don't
fit. Q-5 (`DECISIONS.md`) already sets the dividing line: **combat and
condition rules stay as they are; economy, recovery, and travel get
adapted.** This file draws that line in practice, section by section, and
proposes what the adapted side looks like. `D1` (Bases) and `F1` (Travel &
Downtime) build the full detail on top of what's proposed here; this file
sets the shape they both have to agree with.

## What Stays Untouched

Per Q-5's default, nothing below changes for the surface. These are
character-level and encounter-level systems, not Salts-loop economy, and the
novel's three leads all demonstrate them working perfectly well above
ground:

- **Combat and limb targeting.** Lloyd takes a broken arm on the surface in
  ch. 24–25, not inside the Salts; the targeting and status-effect rules
  that produced that already work outdoors, indoors, on a train platform,
  anywhere. No surface variant needed.
- **Status effects and stopwatch parry.** Same reasoning — these are
  combat-resolution mechanics, not location-dependent ones.
- **The six attributes and chargen bones.** A PC is built the same way
  whether the campaign ever visits a thin site or not.
- **Insight.** Canon is explicit that Insight is a personal capacity to
  perceive what's actually there (`novel/canon.md` §5), not a Salts-granted
  power — Lloyd has had it since nineteen, years before any chalice. It
  carries over unmodified. What changes on the surface is purely social: per
  `DECISIONS.md` D-7, Insight is mechanically true in-game and socially
  disbelieved by surface NPCs. That's a roleplaying and reaction-table
  default, not a rules adaptation — nothing for this file to build.
- **Mutation.** Held Salts-side by default rather than adapted — see "Mutation
  and the Salts Loop" below. This is a judgment call this session is making,
  not something Q-5 already settled, and it's logged as a default
  accordingly (`DECISIONS.md` D-14).

## What the Surface Replaces

Four pieces of the Salts loop don't survive contact with a campaign that
travels real roads over real seasons. `DECISIONS.md` D-10 already names the
shape of each replacement; this file fills in how each one actually works at
the table. All four remain `(untested)` until played.

### Tokens → Crowns and Favours

The Salts loop's Token economy tracks something consumed entirely inside a
run — it has no unit that means anything once a PC steps back outside. The
surface economy needs two units instead of one, because the novel's own
economy already runs on both: money that changes hands (Edie's ledger,
`source-bible.md` → Objects, prices every job, fare, and favour in crowns)
and obligation that doesn't (the whole cast survives on debts owed and
debts called in — Ferrick's household, the Valley Trust's quiet
cooperation, a bonesetter who owes someone a favour).

- **Crowns** are ordinary money: wages, bribes, travel fares, equipment,
  medical bills. Spend them the way the novel does — Edie's itemised
  "Paid out" ledger (`source-bible.md`) is the model for what a crown buys
  and how plainly it gets written down. `F1` sets the actual price list;
  this file only establishes that crowns exist as the surface's hard
  currency and that nothing Salts-side (Tokens) converts to them directly.
- **Favours** are owed, not spent from a pool — a favour is "the Valley
  Trust's clerk who remembers you helped bury a bad week" or "the broadsheet
  editor who owes the party for the Ascension House story," tracked as a
  short DM-visible list per NPC or faction rather than a number on a
  character sheet. Calling one in costs the relationship, not a resource
  tick: using it up can close that NPC off, strain it, or (rarely) turn them
  into a standing ally, DM's call per the specific favour and faction
  (`C2`'s six factions are the default list of who favours come from).
  `(SYS?)`: whether the ruleset wants a hard favour-tracking mechanic
  (a die size, a tier) or whether this stays pure DM judgement is for the
  real ruleset to decide once it exists.

### The Hub → Safehouses

The Salts loop's hub is a fixed, safe return point between runs. The surface
has no single equivalent — per `DECISIONS.md` D-6, the campaign deliberately
has no single hub, and Stillwell Hydro is one base among several, not the
one true home base. `D1` (Bases & Safehouses) will do the real work of
naming and detailing the starting base and its 2–3 alternates; this file's
job is only to set the rule those bases follow: **a safehouse is wherever
the party has standing, not wherever is geographically central.** Downtime
recovery, resupply, and any between-session advancement happen at a
safehouse the same way they'd happen at the Salts hub, but which location
counts as a safehouse can change as the campaign moves between Parts/regions
— a safehouse in Region I doesn't help the party once play has moved to
Region III, the same way a Part's antagonist and locations don't carry
forward either. `D1` sets how many safehouses exist and what each one costs
to keep; this file just establishes that "the hub" becomes "wherever you've
built standing," not a building with a fixed address for the whole
campaign.

### Bail-Out → Flight, Capture, and Recovery

Bail-out lets a Salts run end instantly and safely the moment it goes wrong.
The surface has consequences that don't vanish that cleanly — nobody in the
novel gets teleported out of a bad situation; they run, they get caught, or
they pay to recover. The surface replacement is three linked outcomes for a
scene that's gone against the party, rather than one safety valve:

1. **Flight.** The party disengages and the scene ends on the opposition's
   terms — they keep whatever ground, evidence, or leverage they already
   had going in, but gain nothing further and the clock(s) in play (`C2`)
   advance as if they hadn't acted. Costs time and, usually, a resource
   (a horse left behind, a safehouse now known to the people chasing them).
2. **Capture.** Per faction, not generic — the Church's crisis-PR instinct
   (`C2`, `hooks.md` #5) means a PC captured by Church-adjacent people is
   more likely to be processed, named, and released with a cost than
   quietly disappeared, while the Valley Trust or an Attrition-scarred pest
   encounter has no such restraint. Capture should always be survivable and
   should always cost something specific and visible — a debt, a record, a
   favour spent to get out — never a blank "you wake up in a cell with no
   explanation."
3. **Recovery.** The surface analogue of healing wrong after a Salts
   injury: hurt taken on the surface is real, takes real downtime, and may
   leave something behind (a limp, a debt to whoever patched you up, a
   favour owed). `F1` sets the actual recovery-time and cost tables; this
   file only sets that recovery is never instant and never free, mirroring
   the Salts loop's own "injuries taken inside are real on surfacing and can
   heal wrong" rather than softening it for the surface.

`(SYS?)`: exact DCs, damage thresholds, and recovery-time numbers all wait
on the real ruleset. The shape above — three distinct outcomes replacing one
universal escape hatch — is the proposal; the real ruleset decides when each
one triggers.

### No Fast Travel → Real Travel

The Salts loop has no travel because a run doesn't need any. The surface is
built entirely around travel — `C1`'s rail trunk and coach road, the
multi-day legs between regions, the Northern Road's waypoint towns existing
specifically so travel has texture rather than being an edit cut. This file
sets one rule: **travel takes the time `C1` says it takes, and something
happens during it.** A leg of travel is never pure downtime between scenes;
it is where random encounters (`C2` Clock 5, the Pest Pressure Clock), casual
faction contact, and the Attrition's unhealed ground (`C1` → "Scars of the
Attrition") get their stage time. `F1` builds the actual travel tables,
costs, and encounter frequency; this file only rules out "fast travel" as a
surface option at all, in both directions — there is no narrative-time skip
across a leg `C1` gives a real duration to, the same way the Salts loop
itself never allowed one.

## Mutation and the Salts Loop — Staying Salts-Side

**Session default — D-14 (`DECISIONS.md`).** The ruleset's mutation system
(`A1`'s list of ruleset components) is bound tightly enough to the Salts'
own unstable physics — the chapel that's never quite the same room twice,
injuries that heal wrong, a chalice gift built from reaching into something
that isn't ordinary matter — that this file defaults it to staying
Salts-side rather than inventing a surface trigger for it. The surface has
its own sources of lasting change (a chalice cost, paid once, per `C3`'s
D-13; an injury that heals wrong per Flight/Capture/Recovery above), and
those cover what a surface character needs without reaching for a mechanic
built for a dream-state that doesn't obey ordinary cause and effect. Thin
sites (`T1`–`T3`) run the Salts loop unmodified, mutation included, per
`C3`; nowhere else in the campaign should mutation trigger. Jake can
overturn this if the real ruleset's mutation system turns out to have a
surface use this file hasn't anticipated.

## A Procedure for Chalice Abilities (untested)

`C3`'s D-13 sets the rule (bespoke per recipient, never a menu) and names
this file as the place a build procedure could live. Proposed, `(untested)`,
for the DM to use when a PC drinks at a thin site:

1. **Name an ordinary function.** Pick something the character's body or
   mind already does — grip, sight, memory, balance, speech — the same way
   Lloyd's gift starts from "an arm."
2. **Invert or extend it, once, specifically.** Not a new category of power;
   a change to how that one function works. Lloyd's arm doesn't grant a new
   sense or a new kind of damage — it makes one existing limb able to pass
   through solid matter. Keep the change this narrow.
3. **Pair it with an equally specific, permanent cost that uses the same
   function.** Lloyd's cost isn't generic ("you take a penalty") — it's
   mode-confusion and dropped objects, the same arm(s) misbehaving in a way
   that's the mirror of the gift. A chalice ability that costs something
   unrelated to what it grants is being built wrong per `C3`'s own DM note.
4. **Check it against Lloyd's shape before finalising.** If the result reads
   as a clean upgrade with an attached tax, it's wrong; if it reads as a
   capability and a permanent, specific price that are obviously the same
   coin flipped over, it's right.
5. **Never reuse Lloyd's own pair.** No second PC gets the ethereal arm,
   exactly as `C3` requires — this procedure exists to build a new pair
   every time, not to generalise Lloyd's into a reusable template.

`(SYS?)`: whatever the real ruleset uses for stat blocks or ability
write-ups should format the result; this procedure only decides the content,
not the sheet it ends up on.

## DM Notes

**This file proposes shape, not balance.** Nothing above has been played.
Treat every replacement mechanic as a first draft to be broken at the table
and fixed afterward, not as a finished system — that's what `(untested)`
means throughout.

**Don't let the surface economy quietly become the Token economy.** Crowns
and favours should feel like the novel's own economy (specific, itemised,
morally weighted — Edie's ledger, not an abstracted currency), not like a
re-skinned resource pool the party farms between thin sites.

**When in doubt, ask what the novel's three would have done.** None of them
ever fast-travelled, bailed out of a bad situation, or returned to a fixed
hub. They walked, they got hurt and recovered badly, and they owed people
things. That's the standard this file is translating into rules, not adding
onto.
